# 니즈푸드 에이전트 V3

make_best2_agent를 기존 니즈푸드 급식 제조 에이전트에 적용했다. 원본 DB, 기존 배합·원료 조회, 복합질문, 실시간 음성 및 저장 업무 API를 보존한다. 검증은 별도 임시 DB에서 진행하며 기존 수정 DB와 하위 고려솔더 프로젝트는 변경하지 않는다.

## 보고서

`POST /api/reports`의 kind와 기준은 다음과 같다.

| kind | 보고서 | 날짜 기준 |
| --- | --- | --- |
| production | 일일생산 | 메뉴의 급식 기준일. 배치 계획·현재 등록 실적·상태·시작/종료시각 |
| quality | 품질검식 | 검사시각. 검체 수·결과·이슈 |
| cooking | 조리측정 | 측정시각. 배치·설비·온도·교반·압력·모터 원본값 |
| inventory | 원료재고 | 현재 등록 스냅샷. 날짜 필터 불가 |
| shipments | 출하계획 대비 실적 | 출하예정일. 계획과 현재 등록 누적 출하량 |

재고 외에는 YYYY-MM-DD 기준일이 필요하다. 날짜 없는 대화는 선택 UI를 표시한다. 오늘/어제는 한국 시간 기준이며, 기록이 없으면 404로 안내한다. 출하예정일 기준 누적 실적을 해당 날짜의 실제 출하량이라고 표시하지 않는다. 조리 원본에 단위·허용기준 필드가 없어 단위와 적합 판정을 추정하지 않는다.

배치 필터는 생산·품질·조리에서만 지원한다. 재고·출하를 배치에 임의 배분하지 않는다. 원료 LOT 전체 계보, 영양·알레르기·보관기한·안전 조리조건은 추가 승인 자료가 필요하다.

대화, 왼쪽 보고서 목록, 보고서 화면을 같은 생성 API에 연결했다. Excel은 니즈푸드 기본 양식과 원본 스냅샷 시트, PDF는 한국어 반복 머리말과 페이지 번호를 제공한다. 고객 승인 양식을 재현한 것은 아니다. 진행/오류/완료 시각/문서 ID/다운로드 상태를 표시한다.

`v3_report_exports`에 원본 JSON을 보관하므로 원본 수정 이후에도 이전 보고서는 동일한 기록을 사용한다. 기존 WorkStore 로그인 사용자가 생성한 문서는 소유자 ID를 검사한다. 로그인 필수 정책은 기존 V2_REQUIRE_LOGIN을 따른다. 비로그인 모드의 문서는 추측 불가능한 ID로 조회되며 개인 문서 권한 체계를 대신하지 않는다. 실제 자료 도입 시 기존 로그인 정책을 활성화하고 보관·삭제 기간을 정해야 한다.

## 연구소

품질 원인 조사, 급식 개선 공방, 한 끼의 여정, 업무 브리핑. `POST /api/studio`는 LangGraph 자료 조회 → 사실/창작 분리 → 근거 ID 검사를 사용한다. 조회 실패와 0건을 구분한다. 공방 기본값은 기획 템플릿이며 서버 AI 설정 시 새 콘셉트를 생성할 수 있다. 실패를 성공으로 숨기지 않는다. 화면 전환 시 음성은 종료하고 대화는 유지한다.

현재 원본은 2026-09-03 중심의 가상·미승인 샘플이다. 개선 초안·원인 후보를 실제 판정이나 제조 변경 승인으로 사용하지 않는다.

## 검증

Python 회귀 테스트, TypeScript/Vite 빌드, PC/390px 모바일 연구소·보고서·대화 유지·파일 다운로드, 소유자 격리, 날짜/배치 범위, 스냅샷 보존을 확인했다. 구형 Streamlit 회귀 테스트는 최신 테스트 도구에서도 동작하도록 app.py 경로를 절대 경로로 지정했다.

실제 마이크·운영 PostgreSQL 검증 및 커밋·푸시·VPS 배포는 이번 로컬 업데이트에 포함하지 않았다. Docker COPY에 새 API 모듈을 추가했다.

## 경동 방식으로 대화 구조 재구성

- API 라우터(api.py) → 대화 서비스(chat_service.py) → LangGraph 복합질문/근거 조회(domain.py, compat.py)로 책임을 분리했다. 기존 니즈푸드 조회 데이터와 저장 업무 호환 경계는 보존한다.
- 대화는 경동과 같은 단일 메시지 배열·취소 세대·요청 잠금 구조로 다시 작성했다. 기존 모바일 서랍용 Assistant 패널과 녹음 상태가 섞이던 구조를 제거했다. LOT를 변경하며 추천질문을 누르면 입력만 준비하고 전송하지 않던 문제도 수정했다.
- API 클라이언트는 apiClient.ts 하나로 통일했다. 접근코드, 로그인 쿠키, JSON 오류, 시간 초과와 취소를 같은 경로로 처리한다. v3request.ts는 호환 어댑터다.
- /api/connection/check는 실제 서버 모델 호출을 수행하고 인증/한도/모델 연결 실패를 구분한다. 키 존재 여부만으로 연결 성공이라고 표시하지 않는다.
- API 경로는 엔트리 스크립트의 배포 경로를 기준으로 계산해 HTTPS 서브경로와 상세 링크에서도 보존한다.
- 1440×1000에서 중앙 대화 폭 940px, 답변 스크롤 높이 약 567px를 확인했다. 1100px 이하에서는 보조 패널을 서랍으로 전환하고, 모바일 입력창은 화면 하단에 유지한다.

실제 서버 키로 모델 응답 및 /api/connection/check, /api/chat의 생산 계획·실적 비교 요청(근거·비교표)을 확인했다. API 주소 서브경로와 공통 인증 헤더도 브라우저 통합 테스트로 검증했다.
