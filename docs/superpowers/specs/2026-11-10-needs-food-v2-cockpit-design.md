# 니즈푸드 V2 제조 AI Agent Cockpit 설계

작성일: 2026-11-10
상태: 설계 승인됨

## 1. 목적과 성공 기준

니즈푸드 제조 AI Agent를 임진강김치 V2와 같은 업무형 3단 화면, 근거형 대화, 한국어 실시간 음성 흐름으로 확장한다. 니즈푸드의 급식·제조 데이터 의미와 기존 읽기 전용 도구는 유지하고, 회사명만 치환하는 방식은 사용하지 않는다.

성공 기준:

- 데스크톱에서는 지식베이스/데이터허브, 중앙 대화, 질의 이력을 한 화면에서 사용할 수 있다.
- 모바일에서는 자료·질문 패널을 열고 닫으면서 질문, LOT/배치 선택, 근거 확인을 수행할 수 있다.
- 직접 입력, 추천질의, 질의 이력 재질문이 하나의 질문 처리 경로를 사용한다.
- 답변은 결론, 확인 내용, 근거, 미확인 사항을 구분하고 데모 자료와 AI 답변을 명시한다.
- 니즈푸드 고유 도구와 필드의 의미를 보존한다. 식/인분/개수와 kg를 혼동하지 않는다.
- 음성 질문은 문자 질문과 같은 중앙 에이전트·도구·근거 계약을 사용한다.
- 현재 승인 배합표·실제 운영 DB가 없는 항목은 합성값으로 채우지 않고 제조 검토용 초안 또는 미확인으로 표시한다.

## 2. 범위와 비범위

### 포함

- `needs-food-ai-agent/v2` React 19 + TypeScript + Vite 7 화면 개편
- FastAPI API와 현재 `needs_agent` 서비스의 연결 정리
- 지식문서·데이터 테이블·규칙·레코드 근거 표시
- 배치/메뉴/원료 문맥 선택과 질문 이력
- 기존 니즈푸드 도구의 읽기 전용 호출과 엄격한 입력 검증
- WebRTC Realtime 음성 세션, 취소·음소거·자원 정리·오류 표시
- API/프론트 빌드/좁은 화면/음성 lifecycle 검증

### 제외

- 제조설비 제어, 레시피 변경, 출하 승인 또는 자동 품질 처분
- 승인 배합표·수율·품질 기준이 없는 값의 생성
- 이번 단계의 실제 PostgreSQL 운영 연결
- 사용자 조직 SSO와 업무 저장 화면의 완전한 운영 전환
- AWS 배포. 구현과 로컬 검증 후 별도 배포 승인에서 진행한다.

## 3. 현행 상태와 제약

현행 `needs-food-ai-agent/v2`에는 FastAPI, React 화면, 음성 훅, 근거형 API, 업무/측정 모듈이 존재한다. 그러나 다음은 구현 시 명시적으로 처리한다.

- 현재 V2는 SQLite 데모 어댑터를 사용하며 PostgreSQL 클래스는 연결 완료로 간주하지 않는다.
- `App.tsx`의 업무 사용자/업무 보드 연결은 완성 기능이 아니므로 이번 범위에서 업무 인증을 전제로 하지 않는다.
- `V2_REQUIRE_LOGIN=1`을 켜면 로그인 UI 부재로 기록 API가 막힐 수 있다. 검증 실행은 0 또는 미설정으로 하고, 운영 인증은 별도 구현 과제로 남긴다.
- `quantity_kg` 같은 호환 필드명만으로 급식 수량을 kg로 해석하지 않는다.
- 니즈푸드 샘플 문서와 DB는 데모·미승인 자료다. 실제 제조 기준과 섞지 않는다.

## 4. 사용자 경험 설계

### 데스크톱

- 왼쪽 자료 패널: 지식베이스 검색/본문, 데이터허브 테이블 선택/행 미리보기
- 중앙 대화 패널: 제품·메뉴·배치 문맥, 질문 입력, 추천질의, 답변·근거·음성 컨트롤
- 오른쪽 질문 패널: 질의 이력, 생산·품질 추천질의, 문서·규칙 추천질의
- 설정 모달: 서버 AI 연결 상태와 접근 코드 입력. API 키는 입력·저장하지 않는다.

### 모바일

- 중앙 대화를 기본 화면으로 유지한다.
- 자료와 질문 패널은 버튼으로 열고 닫는다.
- 패널 전환·새 질문·LOT/배치 변경 시 진행 중 요청과 이전 문맥이 섞이지 않게 한다.

### 답변 표현

답변의 기본 순서는 `결론 → 계산/확인 내용 → 근거 → 확인할 사항`이다. 배합 환산에는 기준 배치량, 목표량, 중량 기준, 수율 적용 여부, 원료별 단위와 반올림 차이를 표시한다. 측정값과 기준값을 분리하고, 검사 대기나 기준 미등록을 합격으로 표현하지 않는다.

## 5. 시스템 구조

```text
React/Vite browser
  ├─ /api/workspace, /api/documents, /api/tables
  ├─ /api/chat → needs_agent service + read-only tools + evidence
  └─ /api/realtime/session → OpenAI Realtime WebRTC
                                  └─ same text-agent policy and tools
FastAPI v2
  ├─ SQLite demo repository (current implementation)
  ├─ needs_agent/knowledge.py, data_hub.py, factory_tools.py
  └─ server-only OPENAI_API_KEY / access-code validation
```

음성은 별도 에이전트가 아니다. 브라우저가 받은 음성 세션은 전사·질문·답변 표시를 거쳐 동일한 텍스트 에이전트 계약과 읽기 전용 도구 정책을 사용한다. 브라우저에는 API 키를 전달하지 않는다.

## 6. 데이터·도구 계약

유지할 대표 도구:

- `get_inventory_status`: 원료명별 재고를 조회하되 LOT·예약·품질보류 정보가 없으면 사용가능량을 미확인으로 둔다.
- `get_batch_trace`: 정확한 배치 ID의 생산·검사 연결을 조회한다. 김치 LOT 계보로 과장하지 않는다.
- `get_quality_summary`: 날짜·메뉴·검사 유형·표본 범위를 함께 표시한다.
- `get_recipe_cost`: 메뉴 사용량·원가를 조회하되 1식 단위와 kg 단위를 분리한다.
- `get_daily_briefing`, `get_production_delays`, `get_cooking_conditions`: 기준일과 측정 항목을 답변에 남긴다.
- `get_kimchi_readiness`, `calculate_kimchi_materials`, `get_kimchi_lot_trace`: 승인 배합·중량 기준·원료 LOT·품질 기록이 확인된 경우에만 계산/판정을 수행한다.

모든 도구는 읽기 전용이다. 허용되지 않은 테이블·필드·추가 인자는 거부하고, 증거 레코드와 문서 ID를 답변에 연결한다. 도구가 없거나 데이터 어댑터가 없으면 연결된 기능이라고 설명하지 않는다.

## 7. 오류와 안전 경계

- 데이터 조회 실패: `기록을 불러오지 못했습니다`와 재시도 버튼을 표시하고 원인을 사용자용 메시지로 제한한다.
- AI 접근 코드 오류: 코드 입력 안내를 표시하고 서버 키나 인증 헤더를 노출하지 않는다.
- 음성 권한/장치/WSS 실패: 권한 허용, HTTPS/localhost, 재연결을 안내하며 문자 입력을 유지한다.
- 음성 중지/취소 시 WebRTC 연결, 재생, 마이크 트랙과 타이머를 정리한다.
- 답변이 늦게 도착해도 취소된 응답을 화면에 다시 삽입하지 않는다.
- 문서·레코드가 없으면 추측하지 않고 미확인으로 표시한다.

## 8. 검증 계획

### 서버

- `GET /api/health`
- `GET /api/workspace`, `/api/documents`, `/api/tables/...`
- 대표 니즈푸드 질문의 데모 답변과 근거 레코드
- 배치·단위·배합 입력의 불일치 및 미등록 기준 처리
- `/api/realtime/session` 인증·콘텐츠 타입·상류 오류 처리

### 프론트엔드

- `npm run build --prefix v2/web`
- 데스크톱과 390px 폭에서 자료/대화/질문 패널 확인
- 문서 검색·본문, 테이블 선택, 추천질의·직접입력·이력 재질문
- LOT/배치 변경, 새 대화, 근거 펼침, AI 접근 코드 저장/삭제

### 음성

- mock lifecycle: 연결 → 준비 → 발화 → 응답 → 취소 → 종료
- 실제 브라우저에서는 HTTPS 또는 localhost에서 마이크 권한, 한국어 질문 1회, 답변 1회를 확인한다.
- 실제 유료 OpenAI·PostgreSQL·AWS 검증은 실행한 경우에만 완료로 보고한다.

## 9. 단계적 구현 순서

1. 기존 V2 계약과 테스트를 기준으로 화면/API 경계를 정리한다.
2. 3단 Cockpit 화면과 니즈푸드 전용 타입·추천질의를 연결한다.
3. 문서·테이블·배치 문맥과 근거 표시를 보강한다.
4. 음성 훅과 FastAPI 세션 계약을 검증하고 오류/취소 정리를 보강한다.
5. 테스트·빌드·좁은 화면 검증 후 구현 커밋을 만든다.
6. 운영 인증·PostgreSQL·AWS 배포는 별도 승인과 실행 단계로 넘긴다.

## 10. 변경하지 않는 것

- 기존 Streamlit V1, 임진강김치 V2, 다른 회사 프로젝트
- 니즈푸드 샘플 DB의 원본 값과 문서 승인 상태
- 제조·출하·설비에 대한 자동 변경 권한
- 사용자 제공 전까지 없는 승인 배합표, 수율, 품질 기준, 실제 재고
