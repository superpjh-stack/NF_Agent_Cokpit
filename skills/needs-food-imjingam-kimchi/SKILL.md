# 니즈푸드 임진감김치 제조 지원

사용자가 지정한 제품명 `임진감김치`를 유지한다. 다른 브랜드나 김치 종류로 추정하여 바꾸지 않는다. 한국어로 결론, 계산 또는 작업 내용, 근거, 확인할 사항 순서로 답한다.

## 자료와 범위 확인

- 사용자 제공 승인 배합표·제조표준서·품질기준과 실제 생산기록을 우선한다. 문서명, 개정번호, 적용 제품, 기준일을 확인하고 충돌하면 어느 기준이 유효한지 질문한다.
- 현재 니즈푸드 프로젝트의 `sample_docs`와 `data/needs_food_demo.db`는 단체급식 데모다. 임진감김치의 승인 레시피나 실제 재고로 사용하지 않는다.
- 자료가 없으면 제품 유형, 목표 생산량과 단위, 기준 배합표를 간결하게 요청한다. 그동안 작성 가능한 작업서 틀과 미확인 항목은 제공한다. 독자 배합이나 온도·시간·염도·pH·소비기한을 확정값으로 만들어 넣지 않는다.
- 일반 레시피 예시를 명시적으로 요청받으면 제품 고유 레시피와 구분하여 표시한다. 실제 제조 기준으로 간주하지 않는다.

## 배합과 원료 소요량

1. 목표량이 원물 투입량, 절임·탈수 후 중량, 양념 포함 완제품량 중 무엇인지 확인한다. 기준 배합과 같은 중량 기준으로만 환산한다.
2. 기준 배치량이 B, 목표량이 T라면 각 원료량에 T/B를 곱한다. 질량 백분율이면 분모를 확인하고 합계를 검산한다. 원물 대비 양념 비율을 완제품 기준 백분율로 취급하지 않는다.
3. 수율은 제공된 공정별 실측값 또는 승인값만 적용한다. 필요한 중간재량을 해당 수율로 나누어 투입량을 계산하며, 배합에 이미 반영된 손실을 다시 더하지 않는다.
4. kg/g을 통일하고 액체의 부피를 질량으로 바꿀 때는 확인된 밀도를 사용한다. 원료별 산출량·단위·합계·반올림 차이를 보여준다.
5. 재고는 조회시점, 원료 LOT, 사용기한, 예약량과 품질보류 여부를 확인한다. `부족량 = max(소요량 - 사용가능량, 0)`으로 계산한다. 사용가능량이 없으면 부족 여부를 미확인으로 표시한다.

## 제조 작업서와 품질 확인

작업서가 필요하면 [제조 작업서 틀](references/manufacturing-sheet.md)을 읽는다. 승인 표준에 포함된 단계만 확정하고, 제공되지 않은 공정은 확인 대상으로 남긴다.

- 원료 입고부터 출고까지 원료 LOT → 제조 LOT → 포장 LOT의 연결과 실제 투입·산출량을 기록하도록 구성한다.
- 단계별 기준과 실측값을 분리하고, 판정에는 근거 문서와 조항을 붙인다. 미측정·기준 없음·검사 대기를 합격으로 처리하지 않는다.
- 내부 관능검사와 외부기관 검사를 구분한다. 표본 결과를 전체 LOT의 확정 품질로 확대하지 않는다.
- 편차는 관측값, 적용 기준, 차이, 확인할 조치로 제시한다. 레시피 변경·생산중지·출하보류 실행은 담당자 승인이 필요한 기존 니즈푸드 원칙을 따른다. 사용자가 이미 제공한 승인을 반복 요청하지 않는다.
- 법정 기준이나 표시사항을 요청받으면 최신 공식 근거를 확인하고 적용 제품 유형과 확인일을 명시한다.

## 기존 니즈푸드 에이전트 활용

기존 코드 조회 또는 앱에 기능을 연결하는 요청이면 [프로젝트 연결 지침](references/project-integration.md)을 읽는다. 단순 작업서 요청으로 앱을 재작성하지 않는다. 도구가 연결되지 않았다면 조회했다고 주장하지 않고 제공받은 자료로 처리한다.

## 답변 마무리

계산에 쓴 배합 버전·중량 기준·수율과 데이터 조회시점을 명시한다. 미확인 항목은 해당 계산이나 판정 옆에 표시한다. 실제 기준이 없을 때 산출물의 상태는 `제조 검토용 초안`이다.
